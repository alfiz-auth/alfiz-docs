Alfiz is authorization for TypeScript applications. You declare a permission catalog — every permission key, every scope type — directly in your codebase. Every `can()` check runs in-process against your own database. Nothing on your request path ever calls out to an external service.

## Four commitments

<CardGroup cols={2}>
  <Card title="Frame drawn in code" icon="file-code">
    Your permission catalog is TypeScript. Template-literal types verify every key at compile time — no dashboard configuration, no drift.
  </Card>
  <Card title="Checks at the doorway" icon="door-open">
    `can()` runs in-process against your own database. Nothing Alfiz operates is on your request path, and Alfiz can never break your app.
  </Card>
  <Card title="Openings nest" icon="layer-group">
    Grants are stored once at the node where they are made. Ancestor chains are walked at check time — grant broad, query narrow.
  </Card>
  <Card title="Growth adds bays" icon="arrows-left-right">
    The same grant tuple and check shape work across one app or twenty, standalone, linked, or federated. Growth never changes the module.
  </Card>
</CardGroup>

## Get started

<Steps>
  <Step title="Install packages">
    ```bash
    npm install @alfiz-auth/core @alfiz-auth/application
    ```
  </Step>
  <Step title="Define your catalog">
    Declare namespaces, permissions, and scope types in a single TypeScript module.
    See the [Catalog overview](/catalog/overview) to learn the shape.
  </Step>
  <Step title="Create the application and client">
    Wire a storage driver and ancestry resolver, then call `createAlfizClient`.
    The [Quickstart](/quickstart) walks through this end-to-end.
  </Step>
  <Step title="Run your first check">
    ```ts
    const allowed = await alfiz.can({ userId }, "docs.files.read", "docs.doc:123");
    ```
    Every check is typed against your catalog — unknown keys are compile errors.
  </Step>
</Steps>

## Packages

| Package | Purpose |
|---|---|
| `@alfiz-auth/core` | Client: grammar, catalog, check shapes, caches, headless components |
| `@alfiz-auth/application` | Application: local provider against your database |
| `@alfiz-auth/prisma` | Prisma storage driver for the Application |
| `@alfiz-auth/verify` | `alfiz-verify` CLI for static call-site verification |

<Note>
  Runtime checks are **never metered**. Alfiz Cloud meters only work the Service performs — admin seats, hosted connectors, retained audit volume. An idle deployment accrues nothing.
</Note>
